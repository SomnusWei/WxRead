## 一、项目本质

这是一个**微信读书网页版**的自动化刷时长脚本，核心原理是：**模拟浏览器向微信读书官网 API 发送 POST 请求，伪装成"正在阅读"的行为**，从而在排行榜和挑战赛中累积阅读时长。

---

## 二、需要抓取的 Cookie 和 Token

### 1. 必须抓取的 Cookie（来自浏览器开发者工具）

在微信读书网页版（`weread.qq.com`）打开任意书籍后，通过 F12 抓包找到 `read` 接口的请求 Cookie，需要提取以下字段：

| Cookie 名称 | 作用 | 是否关键 |
|---|---|---|
| **`wr_skey`** | **会话密钥（最核心）**，标识当前登录态，过期后需通过 `/web/login/renewal` 接口刷新 | **最关键** |
| `RK` | 微信登录态标识 | 需要 |
| `ptcz` | 微信登录态标识 | 需要 |
| `pac_uid` | 用户唯一标识（格式 `0_` + 用户ID） | 需要 |
| `_qimei_uuid42` | 设备指纹标识 | 需要 |
| `iip` | IP 区域标识 | 需要 |
| `wr_avatar` | 用户头像 URL | 需要 |
| `wr_gender` | 用户性别 | 需要 |

### 2. 必须抓取的 Header

| Header 名称 | 作用 |
|---|---|
| `User-Agent` | 浏览器标识，需与抓包时一致 |
| `Accept` | 请求类型（`application/json, text/plain, */*`） |
| `Accept-Language` | 语言偏好 |
| `Baggage` | Sentry 监控追踪头（含 `sentry-public_key` 和 `sentry-trace_id`） |

### 3. 请求 Body 中的关键字段

向 `https://weread.qq.com/web/book/read` 发送的 POST 请求体中，以下字段是核心：

| 字段 | 作用 | 生成方式 |
|---|---|---|
| **`sg`** | **安全签名**，防篡改校验 | `SHA256(ts + rn + KEY)`，其中 `KEY` 是代码中硬编码的盐值 |
| **`s`** | **请求校验和** | 自定义 `cal_hash()` 函数计算（FNV 变体哈希） |
| `ts` | 毫秒级时间戳 | 当前时间 + 随机偏移 |
| `rn` | 随机数 | `random.randint(0, 1000)` |
| `ct` | 秒级时间戳 | 当前时间（秒） |
| `rt` | 本次阅读时长（秒） | 当前时间 - 上次时间 |
| `b` | 书籍 ID | 从预置书籍列表中随机选取 |
| `c` | 章节 ID | 从预置章节列表中随机选取 |
| `appId` | 应用标识（`wb182564874603h266381671`） | 硬编码 |
| `ps` | 用户会话标识 | 从抓包获取 |
| `pc` | 设备客户端标识 | 从抓包获取 |

## 三、关键核心在哪？

### 核心 1：`wr_skey` 的获取与自动刷新机制

这是整个项目**最重要的令牌**。它的生命周期有限，过期后所有请求都会失败。项目实现了一套自动刷新机制：

```
调用 /web/login/renewal 接口 → 服务器返回新的 wr_skey Cookie → 更新本地 cookies 字典
```

代码中有 3 种不同的 `COOKIE_DATA_VARIANTS` 载荷尝试刷新，确保至少有一种能成功。

### 核心 2：签名生成（防自动化检测）

请求体中的 `sg` 和 `s` 两个字段是**防作弊的核心校验**：

- **`sg`** = `hashlib.sha256(f"{ts}{rn}{KEY}".encode()).hexdigest()`
  - `KEY` = `"3c5c8717f3daf09iop3423zafeqoi"`（硬编码在代码中）
  - 这是一个**固定的盐值**，所有客户端共用，微信读书服务器也持有同样的 KEY

- **`s`** = `cal_hash(encode_data(data))`
  - `cal_hash` 是一个 FNV-1a 变体哈希算法（双旋哈希）
  - `encode_data` 对 data 的所有键值对进行 URL 编码后按 key 排序拼接

### 核心 3：反检测策略

项目在多个层面做了反检测处理：

1. **随机化**：每次请求随机选书籍 ID 和章节 ID，随机 `rn` 值
2. **时间伪装**：`rt`（阅读时长）基于真实时间差，`ts` 加随机毫秒偏移
3. **间隔控制**：每次请求后 `time.sleep(30)`，模拟正常阅读节奏
4. **异常恢复**：缺少 `synckey` 时自动调用 `chapterInfos` 接口修复；cookie 过期时自动刷新

### 核心 4：三个关键 API 接口

| 接口 | 用途 |
|---|---|
| `POST /web/book/read` | **主接口**——模拟阅读行为，提交阅读记录 |
| `POST /web/login/renewal` | **续命接口**——刷新 `wr_skey` 会话密钥 |
| `POST /web/book/chapterInfos` | **修复接口**——处理缺少 `synckey` 的异常 |

## 四、如果要开发独立 APP，你需要做的

1. **抓包获取初始 Cookie**：在微信读书网页版打开一本书，F12 抓包，复制 `read` 接口的完整 curl 命令（包含所有 Cookie 和 Header）

2. **提取关键 Cookie**：至少需要 `wr_skey`、`RK`、`ptcz`、`pac_uid`、`_qimei_uuid42`

3. **实现签名算法**：复刻 `cal_hash()` 和 `sg` 的 SHA256 生成逻辑（KEY 值在代码中是公开的）

4. **实现自动续期**：定期调用 `/web/login/renewal` 刷新 `wr_skey`

5. **注意风险**：
   - 微信读书可能更新签名算法（改 KEY 或改 `cal_hash`），届时脚本会失效
   - 频繁请求可能触发风控，导致账号被限制
   - `appId` 等硬编码值可能被服务端轮换

**总结一句话**：这个项目的核心就三件事——**抓 Cookie（特别是 `wr_skey`）、算签名（`sg` + `s`）、保活续期（`renewal`）**。其他都是围绕这三件事的辅助逻辑。
